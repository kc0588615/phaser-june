### Why

The live database still holds two tables of old test rounds and accounts that no code has read or written since M6 and M11, write grants that served only the deleted save route, and a third of a view that every globe visit reads but nothing asks for. Removing them makes the game's role unable to change a row, whatever its code does, and makes `db/schema.sql` describe what the app uses. Because this changes the live database, each step must be reversible until the wait has shown nothing reads what goes, and players must see no change at all.

### Findings

**F1 (high, design-breaking): the brief's W2 proof can't print `0`, and its `ST_Equals` fallback is unreliable.** The proof's `md5(ST_AsBinary(outline))` assumes the view's outlines are reproducible. They aren't:

```sql
SET LOCAL lock_timeout = '5s';
SET LOCAL statement_timeout = '15min';
CREATE MATERIALIZED VIEW clue_match_places_next AS
WITH playable AS (
  SELECT DISTINCT species_id FROM species_deduction_clues
), ranges AS (
  SELECT s.id AS species_id, i.wkb_geometry AS geom, i.presence
  FROM species s
  JOIN playable p ON p.species_id = s.id
  JOIN iucn i ON i.id_no = s.iucn_id
), kept AS (
  SELECT r.species_id, ST_Union(ST_MakeValid(r.geom)) AS geom
  FROM ranges r
  WHERE r.presence IN (1, 2, 3)
     OR NOT EXISTS (SELECT 1 FROM ranges x WHERE x.species_id = r.species_id AND x.presence IN (1, 2, 3))
  GROUP BY r.species_id
), country_parts AS (
  -- Each polygon of each country, with the continent it actually sits on.
  SELECT c.adm0_a3, c.name, c.continent AS home, d.geom,
         CASE
           WHEN c.adm0_a3 = 'FRA' AND ST_X(ST_Centroid(d.geom)) < -30 THEN 'South America'
           WHEN c.adm0_a3 = 'FRA' AND ST_X(ST_Centroid(d.geom)) > 40 THEN 'Africa'
           ELSE c.continent
         END AS continent
  FROM natural_earth.countries c
  CROSS JOIN LATERAL ST_Dump(ST_MakeValid(c.geom)) d
  WHERE c.continent NOT IN ('Seven seas (open ocean)', 'Antarctica') AND c.adm0_a3 <> 'RUS'
  UNION ALL
  SELECT c.adm0_a3, c.name, 'Asia', ST_Intersection(ST_MakeValid(c.geom), ST_MakeEnvelope(60, -90, 180, 90, 4326)), 'Asia'
  FROM natural_earth.countries c WHERE c.adm0_a3 = 'RUS'
  UNION ALL
  SELECT c.adm0_a3, c.name, 'Asia', ST_Intersection(ST_MakeValid(c.geom), ST_MakeEnvelope(-180, -90, 60, 90, 4326)), 'Europe'
  FROM natural_earth.countries c WHERE c.adm0_a3 = 'RUS'
), areas AS (
  SELECT 'continent'::text AS kind, 'continent:' || lower(replace(continent, ' ', '-')) AS key, continent AS name, 'Continents' AS grp, ST_Union(geom) AS geom
  FROM country_parts
  GROUP BY continent
), lives_in AS (
  SELECT a.key, k.species_id
  FROM areas a
  JOIN kept k ON ST_Intersects(a.geom, k.geom)
  WHERE ST_Area(ST_Intersection(a.geom, k.geom)::geography) >= LEAST(0.05 * ST_Area(k.geom::geography), 5e9)
), place_species AS (
  SELECT key, array_agg(species_id ORDER BY species_id) AS species_ids
  FROM lives_in
  GROUP BY key
  HAVING count(*) >= 2
), largest AS (
  SELECT a.key, (SELECT d.geom FROM ST_Dump(a.geom) d ORDER BY ST_Area(d.geom) DESC LIMIT 1) AS part
  FROM areas a
  JOIN place_species ps USING (key)
)
SELECT a.kind, a.key, a.name, a.grp,
       ps.species_ids,
       round(ST_XMin(l.part)::numeric, 3)::float8 AS west,
       round(ST_YMin(l.part)::numeric, 3)::float8 AS south,
       round(ST_XMax(l.part)::numeric, 3)::float8 AS east,
       round(ST_YMax(l.part)::numeric, 3)::float8 AS north,
       round(ST_X(ST_PointOnSurface(l.part))::numeric, 3)::float8 AS lon,
       round(ST_Y(ST_PointOnSurface(l.part))::numeric, 3)::float8 AS lat,
       ST_SimplifyPreserveTopology(a.geom, LEAST(0.1, GREATEST(0.01, sqrt(ST_Area(a.geom)) / 100))) AS outline
FROM areas a
JOIN place_species ps USING (key)
JOIN largest l USING (key);
CREATE UNIQUE INDEX clue_match_places_next_key ON clue_match_places_next (key);
GRANT SELECT ON clue_match_places_next TO critter_app;
```

**Risks specific to this design:**
- **W5 locks `species`.** Dropping `retired_clue_match_solves` removes its FK to `species`, and with it the RI triggers on `species`, under an ACCESS EXCLUSIVE lock. Every pool and places request queues behind it, for at most 5 s (`lock_timeout`); after that it rolls back. Once the lock is held, the drops take milliseconds. W3 takes the same lock on `clue_match_places` (every globe visit), with the same 5 s cap.
- **A REVOKE that revokes nothing doesn't fail.** It only warns "no privileges could be revoked" when the role running it isn't the grantor. On the dev copy, `critter_dev` became the grantor through `ALTER … OWNER` (dev-role.sql). So the `grants` diff after dev W1 is the proof, not psql's exit code.
- **Timeouts.** The W-files run as `postgres` live (no `statement_timeout`) and as `critter_dev` on the dev copy (60 s). Only W2 and refresh-time.sql run long, and both set 15 min. `critter_app`'s 15 s doesn't apply to any W-file. Live W2's build loads the shared server for about T; nothing refreshes the live view (Out of scope).
- **`species_ids` could change.** If the tiny union differences (F1) moved an animal across the 5% or 5,000 km² line, proof 3 or `live-check` fails, which is correct: the players' place list would change. Then no W3: undo by committed stage, and a handoff item.
- **Dev ahead of live.** Between each dev write and its live write, the dev copy runs ahead of live. CI's e2e uses the dev copy, but the mission opens no PR until the release, after every write, so CI sees the final state.
- **`main`'s `dev-role.sql` until the merge.** Between live W4 and the merge, `main`'s `dev-role.sql` fails at its `UPDATE clue_match_solves` on a freshly copied database. It fails loudly inside its transaction under `ON_ERROR_STOP` and changes nothing, so it only means: don't refresh the copy before the merge. The window is hours.
- **pgBouncer.** `SET LOCAL` is safe under its transaction pooling, because `-1` makes each file one transaction.

## Failure modes

The undo for each write is the Architecture's **Undo by committed stage**. These cases aren't covered there:
- **A session stops partway through a step.** Rule 1 reads the stage from `grants.sql` on both databases before anything else. Each stage w0 to w5 gives a different output, because W2 adds `_next` and W3 adds `retired_clue_match_places`. Running a W-file again on a database already past it fails and changes nothing. An undo runs only after this check.
- **The clock reaches the nightly window.** The guards refuse, and the session waits (rule 3). It never ends a live step halfway to wait.
- **The dump, the pull, the checksum or `restore-check` fails** before W1, or before W5 for the restore check. Then there is no live write: retry once as a network blip, then a handoff item and `MISSION_BLOCKED`.
- **Another E2E or a CI run uses the dev copy** at the same time: rule 2 waits for it.
- **`logs-check.sh` finds a line from after W1** that none of the mission's recorded statements explains. The next write doesn't run: a handoff item and `MISSION_BLOCKED`. Lines from before W1 are recorded at S1.
- **The mission stops before S11.** S2's edits then describe writes that haven't happened. Before any release, revert the edits for those writes, as the owner's answer to the handoff item decides. There is no release from a blocked state.
