### Why

The deploy is how every mission's work reaches players, unattended. Today its check can pass without looking at the website (D12), and can pass with a blank game (A5). The server's disk fills with every build (A8), and the secrets file isn't covered by either ignore file in a public repo (A11). The runbook gives a rollback that the deploy script refuses (S7), and the database stack's file is of unknown accuracy (A12). Each fix makes a gate stricter or a doc true, so every check after the deploy compares with a baseline taken just before the merge. A flaky new gate would revert good deploys.

- **Artifact names on reruns.** If a rerun's `upload-artifact` refuses the existing name `e2e-site`, add `overwrite: true` (also a runner fix).
- **Docker Hub's copy of the pinned digest.** It may one day be garbage-collected; a pull would then fail loudly instead of silently changing the pooler. The server isn't affected, because it runs its own file.
- **The first `builder prune`** removes about 20 GB while players play. That's IO only, after `up`, and a failure only warns.

### Rejected alternatives

- **Playwright, or `cdp.mjs`'s `waitFor`, for the board check:** Playwright needs `node_modules`, which `deploy`'s worktree lacks, and `waitFor` can't fail early or settle.
- **The audit's "sentence in the release steps" instead of a script:** the owner chose the scripted gate (Notes, A5).
- **Passing on the first poll that matches:** it misses a scene that crashes right after the rows render, which is what the exception condition is there for.
- **Retrying a Chrome that won't start:** it isn't the game's failure, and 10 s won't fix it. Stop at once and say the deploy is live.
- **`docker image prune -a` or `docker system prune`:** they would remove the `:previous` images and `caddy:2`, and `system prune` also takes networks.
- **Tagging `:previous` before `build`:** that can't compare with the new id, and it moves `:previous` even when the build then fails.
- **Reading `/opt/postgis/docker-compose.yml` with masking:** forbidden (H9).
- **Pinning by tag:** no tag carries the running digest.
- **A separate CI job for `e2e:site`:** the release waits on `check` only (Goal 4).
- **A `wait-on` dependency for the server:** a `curl` loop under `timeout` is enough.
