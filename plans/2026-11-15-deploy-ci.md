### Why

The deploy is how every mission's work reaches players, unattended. Today its check can pass without looking at the website (D12), and can pass with a blank game (A5). The server's disk fills with every build (A8), and the secrets file isn't covered by either ignore file in a public repo (A11). The runbook gives a rollback that the deploy script refuses (S7), and the database stack's file is of unknown accuracy (A12). Each fix makes a gate stricter or a doc true, so every check after the deploy compares with a baseline taken just before the merge. A flaky new gate would revert good deploys.

#### Goal 6 (A8): the remote part of `deploy/deploy.sh`, and the `:verified` mark at its end

**Two tags, one meaning each.** `<image>:verified` marks the last image that passed every check (`deploy/check.sh`, the board check included). `<image>:previous` is the rollback target: the last verified image before the one now live. Docker health alone isn't enough for `:previous`, because the board check exists for the builds that are healthy and still broken (Astra MUST-FIX 1). `:previous` moves only onto an image that holds `:verified`, so a run of failed deploys can never push the last good image out.

Replace `$compose build -q` / `$compose up -d` (`:34-35`) with:
```bash
$compose build -q
# keep_previous <container>: before up replaces the image <container> runs, keep that image as <image>:previous (the
# hand rollback, docs/DEPLOY.md) if it is the last one that passed every check (<image>:verified, tagged at the end of
# deploy.sh) and it is up (healthy, or running if it has no health check). Otherwise the old :previous stays, so failed
# deploys can't push the last good image out. No container (a first deploy) or a same-commit redeploy changes nothing;
# a failed build never gets here (set -e). The first deploy to find no :verified takes the running image as verified.
keep_previous() {
  local state old name
  state=$(docker inspect "$1" --format '{{if .State.Health}}{{.State.Health.Status}}{{else}}{{.State.Status}}{{end}}' 2>/dev/null) || return 0
  case $state in healthy|running) ;; *) echo "$1 is $state: its :previous stays"; return 0 ;; esac
  old=$(docker inspect "$1" --format '{{.Image}}')
  name=$(docker inspect "$1" --format '{{.Config.Image}}'); name=${name%:*}
  [ "$old" != "$(docker image inspect "$name" --format '{{.Id}}')" ] || return 0
  docker image inspect "$name:verified" >/dev/null 2>&1 || docker tag "$old" "$name:verified"

    echo "$1 runs ${old:7:12}, which never passed deploy/check.sh: $name:previous stays"; return 0
  fi
  docker tag "$old" "$name:previous"
  echo "$name:previous is ${old:7:12}"
}

$compose up -d
```

### Risks

- **A flaky board check reverts good deploys.** The mitigations are 3 attempts, the 10-run proof and the DoD's 2 reruns. A missing Chrome says the deploy is live.
- **Deploys from WSL now need Chrome** (Summary).
- **The `e2e:site` default URL in CI.** It defaults to `http://localhost:3101`, while `site:serve` binds `127.0.0.1`. That works on the Oracle VPS (Baseline 444/444); if the runner resolves `localhost` to `::1` only, set `E2E_SITE_URL: http://127.0.0.1:3101` on the step. That is a runner fix, which Decision rules allow.
- **Artifact names on reruns.** If a rerun's `upload-artifact` refuses the existing name `e2e-site`, add `overwrite: true` (also a runner fix).
- **Docker Hub's copy of the pinned digest.** It may one day be garbage-collected; a pull would then fail loudly instead of silently changing the pooler. The server isn't affected, because it runs its own file.
- **The first `builder prune`** removes about 20 GB while players play. That's IO only, after `up`, and a failure only warns.
- **PgBouncer's certificate renewal** (finding 13) is a production risk outside this mission's scope. The certificate expires 2027-01-24, so H<m> has about two months, and the Summary repeats it. No agent touches certbot or PgBouncer.

### Rejected alternatives

- **Playwright, or `cdp.mjs`'s `waitFor`, for the board check:** Playwright needs `node_modules`, which `deploy`'s worktree lacks, and `waitFor` can't fail early or settle.
- **The audit's "sentence in the release steps" instead of a script:** the owner chose the scripted gate (Notes, A5).
- **Passing on the first poll that matches:** it misses a scene that crashes right after the rows render, which is what the exception condition is there for.
- **Retrying a Chrome that won't start:** it isn't the game's failure, and 10 s won't fix it. Stop at once and say the deploy is live.
- **`docker image prune -a` or `docker system prune`:** they would remove the `:previous` images and `caddy:2`, and `system prune` also takes networks.
- **Tagging `:previous` before `build`:** that can't compare with the new id, and it moves `:previous` even when the build then fails.
- **Reading `/opt/postgis/docker-compose.yml` with masking:** forbidden (H9).
- **Pinning by tag:** no tag carries the running digest.
- **A separate CI job for `e2e:site`:** the release waits on `check` only (Goal 4).
- **A `wait-on` dependency for the server:** a `curl` loop under `timeout` is enough.
- **Moving `:previous` only after `check.sh` passes, with no `:verified` mark:** the remote part would have to pass the replaced id to the local part, which is more fragile than a tag. The tag is also a fact about the image itself, readable on the server.
- **`check.sh` tagging `:verified` itself:** it would make the checker a command (CQS) and would tag on hand reruns and `CHECK_CONNECT` runs.
- **Treating Docker health as "verified":** the board check exists because a healthy container can still serve a broken game (Astra MUST-FIX 1).
- **Changing the repo's PgBouncer mount line now** (the whole `/etc/letsencrypt`, or a copy hook): the A12 rule forbids guessing at the server's copy, and the whole-tree mount likely wouldn't be readable by `USER postgres` anyway.
- **An explicit board-ready signal (Astra SHOULD-CONSIDER):** production has none that a browser can read. The scene's `current-scene-ready` event and `controller.ready` stay inside the bundle, on the module-scoped `EventBus`, and `window.__cc` is dev-only (`debugBridge.ts:1-5`). Adding one would be game code under `src/`, which is out of scope. The 2 s settle with the same-host exception condition covers a scene that crashes after the rows render. Follow-up for a later mission: a `data-board-ready` attribute on the Game board section, set when `setupBoard` finishes, which the check would then require.
